# FAQ・問い合わせ対応の運用

## 初期構成と対象

- 利用者向けFAQ：`/self/help/faq`（ログイン不要）
- 問題・相談の整理：`/self/help/report`（ログイン不要）
- MEO専用の問い合わせメール：`meo.harness@gmail.com`
- `/start`・`/account` の下部からFAQと報告画面へ移動できる。

追加の受付サーバー・メール配信契約・課金は使わない。報告画面はメール本文を作るだけで、受付DB・チケット番号・自動返信は作らない。メールアプリに引き継いだだけでも送信完了とは扱わない。アプリが開けない／本文が途中で切れる場合は、宛先・本文をコピーし、普段のメールサービスから送信する。JavaScriptが使えない場合もメール窓口は表示する。

画面は利用者が記入した内容だけを本文にする。URLのクエリ・認証情報・ログ・ブラウザ情報は自動収集しない。画像アップロード、有人チャット、LINEでの一般相談、AIの自動回答／自動送信は今回の対象外。

公開窓口・返信元はMEO専用メールに統一する。Google管理者招待も同じアカウントで受けるため、問い合わせと招待を区別して確認する。個人用への転送は見落とし防止の補助であり、返信時には差出人がMEO専用になっていることを確認する。転送設定・実受信・返信の到達はそれぞれ確認が必要（今回のローカル変更では未確認）。

## 受信後の手順

1. **実際の受信を確認**してから対応を始める。フォーム確認画面やメールアプリ表示は受信証拠ではない。件名の `[MEO Harness]` は整理用で、本人確認には使わない。
2. 内容を「使い方／接続・認証／LINE／AI返信案／投稿結果／停止・データ」に分類する。停止・誤投稿・個人情報の懸念は優先確認する。対応時間の保証はしない。
3. 発生時刻・該当画面・操作・実際の結果を確認する。足りない情報だけ追加質問し、パスワード・確認番号・APIキー・トークン・認証URL・口コミ全文を求めない。
4. 障害はまず架空データで再現し、失敗条件→修正→自動テスト→該当フローの順に確認する。Googleへの結果が不明な時に繰り返し承認・投稿するよう案内しない。
5. 返信文を人が確認してから、元のメールへの返信として送る。AIに補助を依頼するなら、認証情報や顧客情報を除いた必要最小限の要約を使う。AIの草案は送信許可ではない。
6. 解決後は匿名化した症状・原因・検証結果を記録し、繰り返す質問はFAQへ反映する。メール本文・添付・個人情報をGitや公開Issueへ貼らない。

利用者から「停止・切断・削除」を頼まれた場合も、メールに書かれた店舗名だけで実行しない。可能なら本人にアカウント画面から操作してもらう。ログイン不可なら権限と対象を確認する個別対応とし、確認方法・影響範囲・承認が揃う前に管理操作しない。Googleで公開済みの返信は、このサービスの接続切断では取り消せない。

## 返信の下書き例（自動送信しない）

### 追加情報を確認する

> MEO Harnessについてご連絡ありがとうございます。状況を確認するため、発生した日時・操作した画面・表示されたエラーの文言を、わかる範囲でお知らせください。パスワード・認証コード・確認番号や、お客様の個人情報は送らないでください。画像を添付する場合も同様に隠してください。

### 調査中の案内

> ご報告の状況を確認しています。現時点で原因や解決時刻は未確定です。Googleへの投稿結果が不明な場合は、二重操作を避け、アカウント画面の「最近の返信結果」を確認してください。新たに確認できた内容があれば、このメールに返信してご案内します。

### 修正後の案内

> ご報告の［症状］について、［原因・変更点］を確認しました。［実施した検証］で問題が再現しないことを確認しています。お手数ですが［具体的な再確認手順］をお試しください。改善しない場合は、発生時刻と画面の表示をお知らせください。

角括弧は確認した事実で埋める。ローカルで直しただけなら「公開環境で修正済み」とは書かない。メール受信／原因判明／修正／公開／利用者側の復旧は別々に扱う。

## 公開前のチェック

- [ ] 既存の連絡先を公開窓口として使うこと、確認担当・確認頻度を運営者が最終確認。
- [ ] 運営者の承認後にテストメールを実際に送信し、受信と返信を別々に確認。今回のローカルテストでは実送信しない。
- [ ] 問い合わせメール・添付の保管先、閲覧権限、保存期間・削除手順を決め、正式なプライバシー案内に反映。フォーム側の非保存と受信メール側の保存は別。
- [ ] 本番の `/start`・`/account` → FAQ → 報告 → メール作成の導線を公開後に確認。
- [ ] サービス全体の公開条件は `docs/self-service-release.md` も確認。FAQ追加だけで受付を開かない。

設定の都合で受付方式を後から変える場合も、確認画面と実際の送信・受信を区別し、個人情報の扱いを先に決める。
