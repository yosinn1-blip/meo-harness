# スマホのLINE登録コード入力を補助する案

スマホで登録するときに、コードのコピー・貼り付けと元画面への戻りで迷う問題を、既存の公式アカウントへのボタンで改善する。2026-10-02時点のローカル候補。実スマホの検証・本番反映・チラシ配布は別段階で、完了とは扱わない。

LINE公式の [URL scheme](https://developers.line.biz/en/docs/messaging-api/using-line-url-scheme/) は `https://line.me/R/oaMessage/{percent-encoded LINE ID}/?{percent-encoded text}` で、指定公式アカウントのトークにメッセージを入力する。本人がLINEの送信ボタンを押す。iOS/Android用で、PC版LINEは対象外。LINE未インストール時はダウンロード案内になる。`line://` は使わない。

既存の友だち追加URLから、HTTPSの正しい `line.me/R/ti/p/` と公式アカウントIDだけを取り出す。分からない形式・別のドメイン・query/hash付きにはコードを付けず、既存のコピー方式を案内する。QRは既存の友だち追加QRのままで登録コードを含めない。コードを含むリンクは期限内だけ表示し、クリック時にも確認する。`noopener noreferrer` と `no-referrer` を付けて元の登録タブを保持する。コードは既存APIの応答から画面のRAMだけで扱い、URLは指定LINEトークの入力補助にだけ使う。解析・ログ・永続ストレージへ追加しない。

主な流れは、入口QRから登録画面→Google本人同意と店選択→LINEボタン→本人送信→アプリ切替で元Safari/Chromeの登録タブ。初めての友だち追加で入力が引き継がれなければ元タブのボタンをもう一度押す。PC・未インストール・入力されない場合は補助欄のコピー/友だち追加/画面内QRを使う。期限切れやコードが消えた中断再開は、本人が明示的に再発行する。

戻った際のvisibility/pageshowはstatus GETだけ。表示しないretry待ち時間の差だけでは入力欄を作り直さない。PIN本文を新たに保存しない。新しいコード・PINの送信、PIN照合、利用開始は自動化しない。署名付きWebhook、単回15分コード、owner/session/店舗generation、PIN5分・照合回数、送信枠、明示同意、返信ごとの本人承認は既存のまま。

自動PINがOFFの画面にも有効。ただし、コード送信後に元画面の「確認番号をLINEに送る」→LINEで番号を見る→元画面へ入力するので、LINE訪問2回・アプリ切替4回が残る。自動PINがONなら番号が届くまでLINEに滞在して元画面へ戻る1回の訪問・切替2回になるが、今回はONにしない。

既に友だちの通常経路を比較すると、コード送信までの論理操作はコピー→LINEを開く→貼付→送信の4つから、LINEを開く→送信の2つへ。コピー/貼付の2操作を省く想定。OSの起動確認、長押し、友だち追加など端末差があるため、実タップ・所要時間の測定ではない。紙面のQRは2個から入口1個へ整理できる。既存画面にも友だち追加ボタンはあったため、従来2回のQR読取りが必須だったとはしない。

戻りリンクをLINEへ送っても元のCookieや既定ブラウザを保証できない。元ブラウザを自動で選び直す機能、PIN自動入力、LIFF/LINE Login/新しい恒久アクセスは追加しない。これらは別の設計・権限・費用の検討になる。

実スマホSafari/ChromeのLINE起動・初回入力維持・OS確認・アプリ切替と同一タブ、未インストールの実画面、紙コピー後QRは未検証。通常Chromeの架空fixtureはURL/入力/状態復帰/期限/送信抑止を検証するもので、スマホOSや実LINEの成功証明にはしない。採用する場合は最新本番/登録状態を再確認し、対象ソースと公開文書をレビューして、本番反映と限定実機確認を具体的に承認する。現在の本番状態を過去の解除済み記録から断定しない。
