# 店舗の了承前に行う安全な動作確認

## 今回の範囲

本人より、clomusの店主には未相談、以前のものは使用感を確かめるデモ・プレゼン候補で採用を見送った、と確認。clomusは試用候補に留め、本番登録・Google権限申請・通知・返信は行わない。今回の「ok」は、架空データと本人管理店舗の既存運用に影響しない範囲の検証として扱う。

## 変更していないもの

- 本番Worker version `aebed4ba-5a22-4508-9adc-af876e3fdf2f`。再デプロイなし。
- Google/LINEの権限・Secrets・既存店設定・legacy予約・課金契約。
- clomusの設定、他人の店舗データ、公開口コミ。

本人店舗のダイジェスト待ちバッファは0件だったが、旧承認データを全件点検したわけではなく「旧処理が何も残っていない」とは断定しない。テストと読み取り検証、記録だけなので実装の外部委譲は対象なし。

## 本番運用前に残ること

1. 本人店舗を新自己登録へ接続する方法を決める。Yoshiki Appsは既存運用中なので予約を勝手に解放しない。一時停止/切替をするなら対象・影響・復旧手順を示して別途承認を得る。
2. 現在の本人限定版は接続確認専用。LINEの実送信などを試すには、本人宛・回数・上限を明示した次段階の承認と設定/必要な実装の確認が必要。今回のokを実送信許可へ拡張しない。
3. 承認された環境で、実LINE到達、口コミ取得、停止・切断、旧承認拒否、資格情報削除を確認。実口コミへの投稿は対象と本文の個別承認がある場合のみ。
4. 一般公開のOAuth設定、実残量/上限、プライバシーと保存/復元保持、公開範囲の承認をそろえる。現時点で「記事を見た誰でも登録して即利用可能」とは告知しない。

公開判定スクリプトは `ready:false`、終了1（想定どおり）。未確認の一般公開項目を、試験合格や本人Googleログイン成功だけでtrueにしない。美容院への相談を急がせたり、それを開発全体の前提にしたりしない。

生ログ、元終了コード、公開判定の入力/出力、本番の読み取り結果はignoredの `output/self-service/safe-validation/`。認証情報・Google subject・実口コミ本文は記録しない。スクリーンショットは同ディレクトリの本番読み取り画面と、`output/self-service/desktop-approved.png` の架空試験画面を区別する。
